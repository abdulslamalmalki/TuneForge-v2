# TuneForge v1.33 guidance coverage foundation

## Outcome

Milestone 2 introduces an audited candidate layer between approved BIOS manual
settings and public guidance claims. It processes the complete approved source
library efficiently while preserving the rule that only separately approved
claims enter citation-first answers.

The live generation run on 2026-08-14 produced:

- 4,018 approved source settings processed
- 8,885 atomic candidates
- 1,656 pending human review
- 6,382 candidates requiring additional research
- 847 deterministic duplicates
- 25 generated possible-conflict flags, of which 13 remain in actionable states
- 0 automatic claim approvals
- 17 existing approved claims unchanged
- 42 source settings currently covered by verified claims (1.05%)

Reports are written under `data/reports/` and remain local operational data.

## Trust boundary

Candidate generation copies exact reviewed description text from an approved
source setting. It does not paraphrase or fill missing facts. Missing canonical
mapping, provenance, page review, description, or other mandatory source gates
routes the record to `needs_research`.

The lifecycle is deliberately two-step:

1. A human may promote a trusted candidate to a **draft** guidance claim.
2. A human must separately approve that claim in the existing claim workflow.

Draft, rejected, uncertain, skipped, duplicate, and needs-research candidates
never enter public read models. Every generation, edit, state decision, merge,
and promotion is append-audited.

## Citation model

Migration `0021` adds a source-setting citation link for guidance claims. This
reuses the existing approved manual, source setting, reviewed page, official
URL, and hardware applicability records instead of duplicating manuals into the
tuning-evidence corpus. Existing evidence-passage citations remain supported.

Public citations now identify whether their origin is an evidence passage or an
approved source setting. Existing evidence-passage response fields and values
remain unchanged.

## Reviewer workflow

The protected `/guidance-candidates` queue provides:

- status, vendor, claim-type, and conflict filters
- demand/cross-vendor/category/risk priority ordering
- original manual title, vendor, page, and exact excerpt
- canonical identity, trust state, confidence, hardware scope, and BIOS scope
- existing related claims and possible-conflict notice
- reviewed edit, promote-to-draft, reject, needs-research, uncertain, skip, and
  merge-duplicate actions
- previous/next navigation and append-only event history

No blind bulk approval is provided.

## Operations

Generate or resume candidates with:

```text
python -m tools.generate_guidance_candidates \
  --after-setting-id 0 \
  --output data/reports/guidance-candidates.json
```

Use `--dry-run` to roll back database changes after producing the report. The
generator is idempotent; the verification rerun created zero additional rows.
