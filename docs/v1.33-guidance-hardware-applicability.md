# TuneForge v1.33 reviewed guidance hardware applicability

## Outcome

Milestone 5 adds explicit, reviewer-controlled hardware targets to Guidance
Claims without changing broad source evidence into exact compatibility.
Existing `source_scope` claims remain broad. Legacy CPU-only requests remain
rejected because they have no evidence basis.

An exact or bounded scope now requires:

- `applicability_scope = reviewed_hardware`
- one or more normalized, foreign-keyed hardware targets
- a reviewer-written evidence basis for every target
- the claim's normal approved evidence and human claim review

Supported targets are exact CPU, CPU family/generation, CPU architecture, CPU
vendor, exact motherboard model, motherboard product family, chipset, chipset
family, platform/socket, and motherboard vendor.

## Safety behavior

- Source-scope claims cannot carry exact targets.
- Unknown target IDs fail closed.
- Targets spanning incompatible platforms, CPU architectures, CPU vendors, or
  motherboard vendors are rejected.
- Multiple targets of the same kind are alternatives; different target kinds
  are conjunctive applicability boundaries.
- Public guidance displays the exact target, evidence level, and evidence basis.
- Resolved system context reports matching, incompatible, and broad fact counts.
- BIOS-version applicability remains explicitly unverified until Milestone 6.

No live claims were automatically re-scoped. The current 17 approved claims
remain source-scoped, and the new live target table is empty. This is deliberate:
TuneForge does not fabricate a human applicability review.
