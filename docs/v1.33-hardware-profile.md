# Request-scoped hardware profile

TuneForge's AM5 system context now captures only inputs that correspond to real reviewed
knowledge boundaries:

- one exact normalized motherboard model;
- one exact normalized CPU model on the same platform;
- an optional BIOS version entered literally as firmware displays it; and
- one optional normalized use case shared with Recommendation Claims.

The supported use cases are gaming, productivity, efficiency, quiet operation,
overclocking, undervolting, memory tuning, and stability troubleshooting. Unknown free-form
use cases are rejected instead of being silently normalized or sent to a language model.

## Privacy and incomplete context

The profile is not stored in the database, a cookie, or a user account. It remains in the
current request and explicit page links. TuneForge works normally without a profile; factual
answers remain available and retain their existing scope notices. If a user starts supplying
hardware context, both motherboard and CPU are required so TuneForge never pretends that a
partial identity is an exact system.

BIOS versions remain user-provided and unverified until matched against an explicit reviewed
BIOS scope. The use case is request context only. It does not become evidence, change factual
Guidance retrieval, or enable recommendation output.

The context is carried consistently through:

- My AM5 System;
- Ask TuneForge;
- Guided Answers;
- citation-first Guidance; and
- the versioned hardware, Guidance, and interface APIs.

## Intentionally deferred fields

Memory kit, memory speed, GPU, and cooler type are not collected in this milestone. TuneForge
does not yet have normalized identities or reviewed Recommendation Claim applicability targets
for those components. Adding free-text fields would imply a level of compatibility and safety
reasoning the platform cannot perform.

Those fields should be introduced only with all of the following:

1. normalized component identities and aliases;
2. reviewer-controlled evidence-backed applicability targets;
3. compatibility and scope validation;
4. exact resolver behavior and fail-closed tests; and
5. a demonstrated retrieval or safety decision that uses the field.

This avoids collecting unnecessary data and keeps the profile aligned with TuneForge's
citation-first trust model.

## Validation

Regression coverage verifies normalized use-case acceptance, unknown-value refusal, API
serialization, UI propagation, BIOS/use-case link preservation, Guidance transparency, and the
critical rule that a complete exact AM5 profile still cannot surface an approved recommendation
through the factual Ask TuneForge path.

No schema migration or production data change is required. The existing schema-`0027`
recommendation-foundation archive remains the current recovery checkpoint.
