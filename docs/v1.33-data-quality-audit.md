# Data quality audit

Milestone 14 adds a reusable, read-only audit for persisted knowledge and file
state that sits beside the existing public Library audit.

Run the complete audit with:

```powershell
.\.venv\Scripts\python.exe -m tools.audit_data_quality `
  --output data\reports\v1.33-data-quality-audit.json
```

`--skip-file-hashes` is available for a faster diagnostic pass, but it is not a
substitute for release validation.

## Checks

The quality audit verifies:

- SQLite integrity and foreign keys;
- exactly one extraction run and one applicability projection per manual;
- setting/manual/extraction-run ownership and page ranges;
- every managed manual and Evidence Source file path, size, and SHA-256;
- unreferenced managed files, reported without deletion;
- Evidence Source official-domain policy and reviewer metadata;
- evidence passage ownership, page ranges, and immutable text hash;
- normalized Canonical Setting and alias collisions;
- approved Guidance Claim citations, canonical links, reviewer metadata, and
  exact normalized duplicates including hardware/BIOS scope;
- approved Recommendation Claim citations, hardware scope, reviewer metadata,
  conflict state, and exact normalized duplicates;
- manual applicability targets and motherboard/vendor consistency;
- numeric and dotted-numeric BIOS range ordering;
- trusted-web result counts, official URLs, stale running jobs, and unreviewed
  research leads.

The command then composes these findings with
`tools.audit_public_bios_knowledge`, which remains responsible for official
manual trust, canonical mapping audit history, cross-canonical source-name
conflicts, classification, equivalence citations, and exact public Library
visibility.

## Severity and mutation policy

- `failure` means a release-blocking integrity or trust invariant failed;
- `warning` means an ambiguous duplicate, dangling file, or stale operation
  needs an operator/reviewer decision;
- `informational` identifies ordinary work, such as a research result awaiting
  triage.

The audit never edits database rows, removes files, promotes evidence, approves
claims, or changes mappings. This preserves TuneForge's append-only and
human-review rules.
