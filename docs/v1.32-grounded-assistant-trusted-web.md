# TuneForge v1.32 — Grounded Assistant and Trusted-Web Research

## Outcome

Ask TuneForge now has three deliberately separate result layers:

1. **Verified answer** — exact accepted Guidance Claims and complete citations.
2. **Approved library discovery** — related reviewer-approved Source Settings,
   shown as records rather than generated claims or recommendations.
3. **Live official-source research** — an explicit opt-in surface that is always
   labeled **Not reviewed by TuneForge**.

The first two layers operate entirely from the local TuneForge database. The
third requires internet access but no paid language-model provider.

## Trust boundary

Live research does not modify or bypass the existing interface contract. In
particular, it does not:

- create Evidence Sources, Evidence Passages, Guidance Claims, canonical mappings,
  aliases, or public recommendations;
- present search snippets as verified facts;
- query community sites, blogs, forums, Reddit, or arbitrary domains;
- send retrieved page content to a language model;
- run unless the user explicitly requests official-web research after asking a
  BIOS-, UEFI-, firmware-, motherboard-, or CPU-tuning-related question.

The allowlist covers official AMD, Intel, ASUS, MSI, GIGABYTE, ASRock, American
Megatrends, UEFI Forum, PCI-SIG, JEDEC, DMTF, Insyde, and Phoenix Technologies
domains. HTTPS, default port, credential-free URLs, redirect destinations, and
public DNS resolution are validated before an HTML page is fetched. Responses
have strict time and size limits. Unsupported content remains an official link
only and is never converted into an excerpt.

## Provenance and audit

Migration `0020` adds:

- `trusted_web_research_runs` — normalized query, policy version, status, result
  count, safe reason, and start/finish timestamps;
- `trusted_web_research_results` — publisher identity, official URL, result kind,
  exact excerpt when available, retrieval time, and SHA-256 page hash;
- `trusted_web_research_events` — append-only started and terminal lifecycle
  events.

Research snapshots are intentionally separate from the reviewed knowledge
tables. Promoting a useful source still requires the normal evidence/manual
intake and human-review workflow.

## Public and API surfaces

- `/answer` includes an opt-in official-web checkbox and a second action after a
  refusal. Verified results, approved library matches, and live research have
  different visual labels.
- `GET /api/v1/interface/trusted-web-research?question=...` returns the same
  explicitly unreviewed research record.

## Model-provider posture

No provider is connected in v1.32. This makes the new capability usable at zero
model cost and preserves provider neutrality. A future model may format only
validated reviewed claims under the existing interface contract; live research
must not silently enter that verified model input.

## Intentionally deferred

- generated “best settings” or optimization plans;
- exact motherboard/CPU/BIOS-version recommendations;
- community evidence connectors;
- automatic web-source ingestion or approval;
- model-generated reconciliation, ranking, or paraphrase of live sources.
