# Ask TuneForge evaluation suite

TuneForge now has a versioned, checked-in product evaluation corpus and a deterministic,
read-only runner. The suite evaluates the actual question router, canonical resolver, reviewed
Guidance retrieval, citation-safe presentation envelope, hardware/BIOS scope behavior, and
approved Library fallback.

## Corpus

`evaluations/ask_tuneforge_v1.json` contains 54 explicit ground-truth cases. It covers the
roadmap's common BIOS topics plus:

- canonical names, approved aliases, and vendor-specific names;
- incorrect terminology and harmless trademark typography differences;
- ambiguous questions and unsupported hardware;
- approved answers, Library-only matches, and insufficient evidence;
- hardware-context and BIOS-version boundaries;
- recommendation requests and risky tuning requests; and
- safe refusal when reviewed recommendation knowledge is unavailable.

Expectations are data, not code: each case declares the expected outcome, resolution state,
canonical identity where applicable, required claim types, minimum fact count, citation
requirement, Library matches, suggestions, equivalence coverage, and scope statuses.

## Independent safety checks

The runner does not trust the presentation envelope merely because the application produced it.
For each statement it independently verifies:

- the claim still exists and is approved;
- claim text and type are unchanged;
- the claim is linked to the returned Canonical Setting;
- every evidence-passage citation has an approved source and matching page/hash/URL; or
- every source-setting citation points to an approved setting, correct manual/page, and a
  recomputed SHA-256 of the reviewed description.

Evaluation intentionally bypasses append-only refusal logging. Running the suite therefore
cannot contaminate unanswered-question demand metrics.

## Metrics

The CLI reports:

- retrieval accuracy;
- canonical resolution accuracy;
- citation accuracy;
- unsupported statement rate;
- answer completeness;
- safe refusal accuracy;
- hardware-scope correctness; and
- vendor-equivalence accuracy.

Run it with:

```powershell
.\.venv\Scripts\python.exe -m tools.evaluate_ask_tuneforge `
  --output data\reports\ask-tuneforge-evaluation.json
```

## Baseline and improved result

The first run found two real retrieval defects while all grounding and refusal metrics remained
clean:

| Metric | Baseline | Improved |
|---|---:|---:|
| Retrieval accuracy | 52/54 (96.30%) | 54/54 (100%) |
| Canonical resolution | 27/28 (96.43%) | 28/28 (100%) |
| Citation accuracy | 19/19 (100%) | 19/19 (100%) |
| Answer completeness | 19/19 (100%) | 19/19 (100%) |
| Safe refusal | 35/35 (100%) | 35/35 (100%) |
| Hardware-scope correctness | 3/3 (100%) | 3/3 (100%) |
| Vendor-equivalence accuracy | 11/11 (100%) | 11/11 (100%) |
| Unsupported statement rate | 0/47 (0%) | 0/47 (0%) |

The fixes are deliberately narrow. Library fallback now searches the question router's exact
setting hint before broader question terms. Canonical lookup may ignore only registered and
trademark typography, and still resolves only when all reviewed matches identify one unique
Canonical Setting. It does not expand acronyms, create aliases, or infer vendor equivalence.

The machine-readable comparison is preserved in
`evaluations/ask_tuneforge_v1_comparison.json`.
