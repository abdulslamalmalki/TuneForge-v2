# Public read-path performance

Milestone 16 profiles and optimizes TuneForge's highest-traffic read paths
without changing the schema, public contracts, review state, or trust model.

Run the repeatable, read-only profile with:

```powershell
.\.venv\Scripts\python.exe -m tools.profile_read_paths --iterations 5
```

The profiler warms each operation once, then reports wall-clock latency from
`time.perf_counter()` and SQL statement counts from SQLAlchemy's engine events.
Results are machine- and corpus-dependent; they are an engineering comparison,
not a service-level guarantee.

## Root cause

The canonical Library projection loaded all approved Source Settings and then
performed identity, detail, alias, vendor-equivalence, classification,
applicability, and guidance reads per canonical identity. On the production
corpus this created 2,993 SQL statements for one catalog request. Canonical
detail also projected all 4,018 approved Source Settings before selecting the
requested identity.

The database and indexes were not the limiting factor. The fix batches existing
approved read models and applies pagination before expensive projection:

- unfiltered Source Settings select only the IDs for the requested page;
- unfiltered canonical browsing selects the canonical page before source
  projection;
- aliases, vendor equivalences, guidance coverage, and manual applicability are
  loaded in bounded batches;
- canonical detail selects only settings mapped to the requested identity; and
- filtered searches preserve their existing semantics while removing
  per-identity database reads.

No cache was added, so review changes remain immediately visible. No new index
or migration was necessary.

## Production-corpus measurements

Measurements used the same local SQLite database with 4,018 approved Source
Settings and 331 active canonical identities. Values are five-run warm averages.

| Read path | Before | After | SQL before | SQL after |
|---|---:|---:|---:|---:|
| Source browse | 97.1 ms | 6.5 ms | 41 | 10 |
| Source search | 28.4 ms | 24.4 ms | 21 | 13 |
| Canonical browse | 1,244.2 ms | 17.9 ms | 2,993 | 14 |
| Canonical search | 1,261.5 ms | 129.9 ms | 2,993 | 14 |
| Canonical detail | 106.0 ms | 12.5 ms | 53 | 18 |
| Source detail | 2.8 ms | 2.5 ms | 7 | 6 |
| Verified Ask lookup | 20.0 ms | 18.7 ms | 11 | 11 |
| Admin dashboard | 42.5 ms | 38.7 ms | 48 | 48 |

Canonical browse latency decreased by about 98.6%, and its SQL count decreased
by about 99.5%. The complete public-knowledge audit decreased from about 44.4
seconds to 5.5 seconds because it traverses the same public read model.

## Regression protection

The public Library integration suite creates multiple reviewed canonical
identities and mappings, calls the real public API, and enforces a fixed query
budget. This catches growth proportional to the number of identities or manuals
while continuing to verify that only reviewer-approved knowledge is returned.

Validation includes the full test suite, Ruff, the Ask evaluation suite, and the
complete public-knowledge audit. The known reviewed ASUS label conflict remains
an intentional warning, not a failure or an inferred mapping.
