# TuneForge v1.5.1 Trust and Public Visibility Audit

## Outcome

The audit passed with no trust, integrity, mapping-history, citation, or public
coverage failures.

| Measure | Result |
| --- | ---: |
| Official manuals with approved settings | 12 |
| Trusted approved Source Settings | 4,018 |
| Source Settings visible in the public Library | 4,018 |
| Active Canonical Settings | 56 |

Public visibility is exact: the set of IDs returned by the public Source
Settings Library equals the set of approved Source Settings, and the set of IDs
returned by the public Canonical Library equals the set of active Canonical
Settings. Draft and rejected records remain inaccessible through both public
HTML and API detail routes.

## Evidence and equivalence guarantees

Every mapped source record is approved, acceptance-certified, and backed by a
stored PDF whose size and SHA-256 match its provenance record. Every source URL
uses HTTPS on the configured official ASUS, ASRock, GIGABYTE, or MSI domain.
Every current mapping has append-only mapping history and a non-empty audited
decision note. Public vendor-equivalence projections include one official
manual citation for every mapped Source Setting.

This audit does **not** claim that all 4,018 records have a cross-vendor
equivalent. Only the 243 reviewed mappings are presented as canonical
equivalence. The remaining 3,775 approved records are fully searchable and
cited, but remain unmapped until sufficient evidence supports an equivalence.
TuneForge continues to prefer an explicit gap over a guessed relationship.

## Corrections applied

- Restored official descriptions for Source Settings 462, 464, and 720 after
  visual review of ASRock page 63 and ASUS page 24.
- Rejected Source Settings 823 and 1077 because the cited ASUS pages show group
  headings rather than configurable settings. Their actual configurable child
  settings remain approved.
- Rejected Source Setting 4901 as an exact adjacent repeat of the retained MSI
  `tXPDLL` source record 4900.
- Preserved 13 same-page repeated labels that official manuals intentionally
  show in distinct menu contexts or as distinct controls. Each disposition is
  pinned in the audit command rather than hidden by a broad deduplication rule.
- Changed exact-name normalization so parenthesized positive and negative signs
  remain semantic. `Max CPU Boost Clock Override(+)` and
  `Max CPU Boost Clock Override(-)` now resolve only to their respective
  reviewed Canonical Settings.

All data corrections used the normal reopen, edit, approve, reject, and
acceptance-certification domain workflows. Extracted source values remain
unchanged, review history is append-only, and the pre-change archive makes the
operation reversible.

## Known official-document conflict

ASUS Intel 600 Series BIOS Manual page 38 prints `Negative Ratio Offset A` in
both the Temperature A and Temperature B branches. The second record's body and
dependency text explicitly refer to Temperature B and `Negative Ratio Offset
B`. TuneForge preserves the printed source label, reports the conflict, and
keeps both records unmapped. It does not silently rewrite the vendor manual or
infer an equivalence from contradictory evidence.
