## 2. Baseline

The verified v1.32 starting architecture used schema `0020`, exposed 4,018 approved
Source Settings, 331 active Canonical Settings, 1,206 mappings, and 2,812 approved
unmapped settings. The inherited full suite was approximately 628 tests. The public
knowledge audit and SQLite integrity gates passed at baseline.

The v1.33 release candidate uses schema `0027` and 738 passing tests.

## 3. Guidance Coverage

The release did not manufacture or auto-approve public facts. Approved claims remain
17, covering 14 of 331 active canonical identities (4.2%). At source-setting level,
42 of 4,018 approved settings have at least one verified-claim relationship (1.05%).

Automation now generated 8,885 audited candidates over the corpus:

- 1,656 pending human review
- 6,382 needing research
- 847 deterministic duplicates
- 13 marked as possible conflicts
- 0 automatically promoted

The pipeline extracts atomic manual-backed facts, binds exact excerpts/pages, records
confidence and priority, detects duplicates/conflicts, and preserves the distinction
between machine-generated candidates and human-approved claims.

## 4. Canonicalization

- Starting mapped: 1,206
- Starting unmapped: 2,812
- Investigated/classified: 2,812
- New verified mappings: 0
- Remaining unmapped: 2,812

System-assessed outcomes are 1 strong candidate, 29 needing human review, 803 needing
research, 935 conflicts, and 1,044 with insufficient evidence. Three existing exact
alias suggestions await review. No confidence gate was weakened and no uncertain
identity was published merely to increase coverage.

## 5. Research Promotion

Official-web results now have an append-only reviewer intake path into a proposed
Evidence Source, immutable passage, and draft claim. Promotion is explicit and cannot
bypass provenance, extraction, citation, or claim review. One official result is
currently awaiting triage; no research result was silently converted into verified
knowledge.

## 6. Hardware Applicability

Guidance and recommendation schemas now support reviewed targets for CPU model/family/
architecture/vendor, motherboard model/family/vendor, chipset/family, and platform.
Evidence level and basis remain explicit. Existing 17 approved legacy claims have no
new structured target rows, so the dashboard truthfully reports zero reviewed
hardware-scoped approved claims rather than inferring scope retroactively.

## 7. BIOS Version Awareness

Claims and recommendations can carry exact, introduced, changed, deprecated, valid-from,
and valid-until firmware facts with comparison mode and evidence basis. Retrieval can
explain applicability or refuse when scope is unavailable. Existing approved claims
have zero reviewed BIOS-scope rows; no historical version support was invented.

## 8. Recommendation Foundation

Recommendation Claims now have action/value/range/unit, use case, risk, prerequisites,
confidence, evidence, hardware scope, BIOS scope, conflict state, human review, and
append-only events. There are zero approved or draft recommendation claims. Public Ask
still refuses “best settings” and tuning actions because an exact reviewed safe resolver
has not been populated and accepted.

## 10. LLM Integration

OpenAI Responses, Anthropic Messages, Gemini `generateContent`, and configurable
OpenAI-compatible adapters are implemented behind one provider-neutral boundary.
Mocked transport and exact-output tests pass. No provider credential was available, so
no live model success is claimed. Refusals bypass providers; invalid, incomplete, or
reordered provider output is discarded in favor of deterministic rendering.

## 11. Admin Workspace

The dashboard now exposes canonical, verified-guidance, direct-evidence, hardware,
BIOS, and recommendation coverage; vendor/platform/chipset footprint; prioritized
active queues; conflicts; official research leads; and demand gaps. Existing review
states and URLs are reused rather than duplicated.

## 12. Data Quality

The reusable audit validates stored hashes, referenced files, extraction ownership,
pages, passage hashes, official URLs, review completeness, citations, duplicate
identities/claims, hardware relations, BIOS ranges, and research lifecycle state.
Final result: zero failures, zero warnings, and one informational official research
lead awaiting triage. The public audit has zero failures and preserves one known
reviewed repeated-label warning.

## 13. Performance

Measured five-run averages on the production corpus:

- Source browse: 97.1 ms / 41 SQL statements -> 6.5 ms / 10
- Canonical browse: 1,244.2 ms / 2,993 statements -> 17.9 ms / 14
- Canonical search: 1,261.5 ms / 2,993 statements -> 129.9 ms / 14
- Canonical detail: 106 ms / 53 statements -> 12.5 ms / 18
- Public knowledge audit: 44.4 seconds -> 5.5 seconds

The improvement uses batch projections and pagination, not a stale cache or duplicated
knowledge store. Query-budget regression coverage protects the result.

## 14. Security

Concrete fixes include method-aware anonymous authorization, POST-only external work,
same-origin model/research invocation, DNS-pinned HTTPS with TLS hostname validation,
redirect revalidation, pinned search transport, upload filename/path confinement, PDF
header and page bounds, URL/open-redirect hardening, production HSTS/COOP/no-store,
startup endpoint validation, configurable bounded rate limits, and privacy-safe
observability. Authentication, CSP, session, same-origin, and append-only protections
remain intact.

The installed and locked dependency sets report no known vulnerabilities and `pip
check` reports no broken requirements.

## 15. UI

## 17. Production Readiness

The repository is a credible v1.33 release candidate for the supported one-instance,
one-worker SQLite topology. It has locked dependencies, non-root/hardened container
definitions, fail-fast preflight, Alembic startup, WAL/full-sync/busy-timeout policy,
health/readiness, structured logs, metrics, rate limits, verified backups, isolated
restore, and deployment/recovery instructions.

Do not call it publicly deployed. Merge should follow human review, a Docker build on a
Docker-capable host, real visual browser acceptance, and deployment-specific recovery
and TLS checks.

## 19. Recommended Next Milestone

The highest-value next milestone is a human guidance-review and official research
campaign, prioritized by cross-vendor identities and user demand. Review the 1,656
pending candidates, research the 6,382 evidence gaps, promote official sources through
the new intake path, and expand the current 14/331 canonical guidance coverage without
lowering trust. Recommendation population should wait until factual, hardware, and BIOS
scope coverage is materially stronger.
